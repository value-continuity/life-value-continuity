## 1. 三つの仕様の責務

| 仕様 | 責務 |
|---|---|
| IB | 何をさせるか（介入・実行の権限と停止状態） |
| LCS | 何を保持し、何を見せるか（データと開示範囲） |
| CCP ライフプロファイル | 誰と、どんな条件で接続するか（相手・目的・保持期間） |

---

## 2. 実効権限は「交差」で決まる

> AI の要求を、そのまま本人の許可とはみなさない。三つの仕様の判定はすべて必要条件であり、どれか一つが拒否すれば実行しない。

判定の順序は次のとおりとする。

1. **CCP**：接続相手・目的・保持期間を検証する
2. **LCS**：対象データと開示範囲を制限する
3. **IB**：介入・実行の権限と停止状態を確認する
4. 許可された範囲だけを実行する

開示段階については、簡略化すると次のように決まる。

```
実効の開示段階 = min（LCS の上限, CCP の既定値または合意値, 本人の同意）
```

ただし、これは開示段階を一列に並べられる場合の簡略表現である。実際には、項目ごとの許可も確認する。

- **上限**（LCS が許す最大値）と**既定値**（CCP の新規接続での初期値）は別のものとして扱う。
- 複数の領域をまたぐ判断では、各領域の境界を個別に確認し、**最も厳しい制約を優先**する。

---

## 3. 原則と技術的強制を分ける

> 本人の主権は、AI の内部的な善意に依存してはいけない。

AI に「守ってください」と頼むのではなく、AI が境界を超えようとしても**実行できない構造**にする。VCDesign の Safety Gate と同じ考え方である。

| 制約 | 実現方法 |
|---|---|
| L1・L2 への書き込み制限 | 権限管理による強制 |
| IB の介入レベルの上限 | 実行前の認可判定 |
| 外部への情報開示 | LCS 側の開示ゲート |
| 委譲の期限 | 期限切れによる権限の失効 |
| 停止・終結 | 処理と接続の遮断 |
| 過干渉の防止 | 応答や通知のポリシー検査 |

ただし、外部に渡した後の情報の扱い（削除の履行など）は、本人側の構造だけでは強制できない。ここは CCP の「宣言と履行の境界」として残る。

---

## 4. 統合テストケース

仕様を足し続けるより、次のケースで三つの仕様を通して検証する。

### ケース 1：外部 AI が資産情報を参照し、リバランスを提案する

| 確認すること | 仕様 |
|---|---|
| 接続相手・目的・保持期間の宣言と受諾 | CCP |
| 資産情報（L0）の開示段階が上限・既定値・同意の交差に収まるか | LCS |
| 資産領域の介入レベルが「提案」以上か、起動条件を満たすか | IB |
| 接続・開示・提案が L3 に記録されるか | LCS |
| 本人が取り消したとき、接続停止と許可の失効が即座に効くか | CCP |

### ケース 2：本人が停止を宣言した後、外部 AI が以前の権限で実行を試みる

| 確認すること | 仕様 |
|---|---|
| 停止状態が実行前の認可判定で必ず参照されるか | IB |
| 以前の許可が失効しており、開示ゲートを通らないか | LCS・CCP |
| 拒否した事実が L3 に記録されるか | LCS |

ケース 2 を確実に遮断できれば、原則が単なる宣言ではなく、実装上の強制力を持つことが確認できる。

### 4.1 「動かないこと」の確認項目

検証で最初に確かめるのは、正常に動くことではなく、**許可がないときに確実に動かないこと**である。

| 状況 | 期待する結果 |
|---|---|
| 本人が接続を許可しない | 外部 AI へデータが渡らない |
| LCS の上限を超えた開示要求 | 上限内に縮小、または拒否 |
| IB の権限を超えた実行要求 | 実行を拒否 |
| 委譲の期限切れ | 権限が失効する |
| 本人が停止を宣言 | 新規の実行を遮断 |
| 停止直前に取得した実行許可 | 実行直前の再確認で拒否 |
| 本人が L1 の価値を変更 | 過去の設定によって変更を妨げない |
| CCP の REVERSE を実行 | 新規の開示を止め、外部での削除の状態を区別する |
