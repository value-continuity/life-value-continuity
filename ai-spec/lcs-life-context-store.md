## 1. 目的

本人の文脈を**本人の手元に保持**し、どの AI に、どこまで見せるかを本人が決められるようにする。

LCS は特定の製品ではなく、ストアが満たすべき仕様である。複数のツールが同じ LCS を読み書きでき、本人はツールを乗り換えても文脈を持ち運べる。

---

## 2. 層

文脈を性質ごとに層に分け、層ごとに保護の強さと書き込み権限を変える。

| 層 | 名称 | 内容 | 書き込み |
|---|---|---|---|
| L0 | 事実 | 予定、生活記録、資産の残高推移、連絡の履歴など | 本人、許可されたツール |
| L1 | 価値 | 守りたい価値、保留、余白の宣言、意図的非最適化 | **本人のみ**（AI は提案のみ） |
| L2 | 判断 | 判断前後の記録（想定・受け止め・Δp・Δn）、評価の追記 | 本人のみ（AI は下書きのみ） |
| L3 | 接続・委譲 | IB の設定、委譲、外部 AI の接続と開示の記録 | ストアが自動で記録 |

- L1 と L2 は本人の判断層であり、最も強く保護する。
- **書き込み権限と下書きの作成を混同しない**。AI が作った下書きは、本人が確認・承認したものだけが L1・L2 に登録される。AI 単独で承認済みにはできない。AI の推測で L1 の価値を確定させない。AI ができるのは提案までで、本人が受け入れたときに初めて登録される。
- L0 の各記録には、**情報源・観測日時・確認状態**（本人確認済み／未確認／推測）を持たせる。事実と推測を区別できないと、誤った文脈が本人の判断を間接的に誘導するため。
- L3 は本人がたどるための記録であり、外部には開示しない。

---

## 3. 開示段階

外部の AI に文脈を渡すときの段階を定める。

| 段階 | 名称 | 渡すもの |
|---|---|---|
| D0 | 非開示 | 何も渡さない |
| D1 | 存在のみ | 「該当する文脈がある／ない」だけを伝える |
| D2 | 抽象化 | 固有の値や意図を落とし、抽象化した問題として渡す |
| D3 | 要約 | 本人が確認した要約を渡す |
| D4 | 原文 | 記録をそのまま渡す |

層ごとの**上限**（LCS が許す最大値）は次のとおりとする。新規接続の**既定値**は CCP ライフプロファイルで定め、上限より低くできる。実際に開示される範囲は共通原則の「交差」で決まる。

| 層 | 上限 |
|---|---|
| L0 事実 | D3 |
| L1 価値 | D2 |
| L2 判断 | D1 |
| L3 接続・委譲 | D0 |

- 上限を上げるのは本人の操作だけで行う。接続ごとに一時的に上げることもできる。
- **抽象化（D2）は手元で行う**。原文は手元から出さず、抽象化した結果だけを渡す。
- **D1（存在のみ）も開示である**。「ある／ない」だけでも機微な情報になりうるため、D1 でも問い合わせの対象・目的・本人の許可を確認する。問いを変えて繰り返す照会による推測にも注意する。

---

## 4. 保管

- 保管場所は本人の手元（端末、または本人が管理する機器）を既定とする。
- 外部に同期する場合は、本人だけが復号できる形でのみ保管する。
- ストアの所有者は本人であり、ツールの提供者ではない。

---

## 5. 記録の扱い

- **記録の非強制**：空の層があっても正常な状態とする。
- **追記**：L2 の評価は上書きせず追記する（LVC 4.2）。
- **消去の優先**：本人が消去を指示した場合は、追記の原則より優先して消去する。終結した目標やルールの記録も、本人の判断で消せる。
- **過去への非拘束**：L1 は本人がいつでも書き換えられる。旧版を残すかどうかも本人が選ぶ。

---

## 6. 持ち運び

- 本人は、いつでも全層を共通形式で書き出せる。
- 書き出したものを、別の LCS 実装に読み込める。
- 特定のツールしか読めない形式での保管を、唯一の保管形態にしない。

---

## 7. 表現案（スケッチ）

```yaml
lcs:
  owner: self
  layers:
    L1_values:
      - id: V-001
        statement: "家族との時間を、仕事の効率より優先する"
        since: 2026-10
      - id: H-001
        type: declared_hold
        statement: "独立の時期は条件が見えるまで保留する"
    L2_judgments:
      - id: J-001
        before:
          expected_outcome: ""
          expected_feeling: ""
          protected_value: V-001
          left_to_chance: ""
        after:
          delta_p: ""          # 予測差分
          delta_n: ""          # 新規発見
          acceptance: ""
        revisions: []          # 追記のみ
  disclosure_caps:
    L0: D3
    L1: D2
    L2: D1
    L3: D0
```

## 8. 未決事項

1. L0 をさらに分けるか（健康・資産など機微度の違うものを同じ層に置いてよいか）
2. 抽象化（D2）の品質を本人がどう確かめるか
3. 共通の書き出し形式を何にするか
4. 家族など、複数人で共有する文脈の扱い
5. L3 の記録形式。CCP ライフプロファイルの記録項目（handshake_id・previous_handshake_id、宣言のハッシュ、宣言と観測の区別、削除要求の状態）を受け取れるようにする
